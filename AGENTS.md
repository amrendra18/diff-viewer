# diff-viewer agent rules

These rules are for any coding agent, or person, that changes this repository.

1. Read `README.md` first: it explains the product, what the app reads, and how it is built. `CONTRIBUTING.md` lists the checks. `verify/features/README.md` maps each feature to its journey in the harness. `.claude/skills/verify-diff-viewer/SKILL.md` explains how the harness launches, drives, and measures the app.
2. Read-only toward every repository the app opens. Git runs through `execFile` with fixed argument arrays, never a shell string. Allowed git commands: `log`, `diff-tree`, `diff-index`, `diff-files`, `cat-file`, `ls-files`, `rev-parse`, `status`, `check-attr`. The app never runs `git diff` or `git show`: plain `git diff` rewrites a stale index (`.git/index`) even with `GIT_OPTIONAL_LOCKS=0`, while `diff-files`, `diff-index --cached`, and `status` leave it unchanged (unit test `stale-index`). `src/app/git-settings.ts` holds the same list, and `scripts/verify` reads the list from the sentence that starts "Allowed git commands:", so keep that sentence's form. Test: `read-only-repository` in `scripts/verify` compares the fixture's `.git` fingerprint before and after, and checks every git command the app runs. `launcher-open` checks the git commands of the `diff-viewer` command and of the app it starts against the same list. Working files are read only when git lists them as changed or untracked; untracked ignored files are never read. A tracked file that matches `.gitignore` is still tracked, so it is read when git lists it as changed. No network request; the same test counts requests and expects 0.
3. The page has no Node access (`contextIsolation` on, `nodeIntegration` off, `sandbox` on). Only the preload exposes a narrow API, `window.diffViewer`. Main validates every message. Test: the `boundary` unit test.
4. Treat commit subjects, author names, paths, and file contents as untrusted text. Render them with `textContent`, or as text inside elements built with `document.createElement`. Never use `innerHTML`; lint refuses it in `src/web/`. Test: the fixture repository holds a file named `<img src=x onerror=alert(1)>.ts` and a subject with HTML, and the `hostile-text` journey checks that no element was created from them.
5. Change process: name the data shape, write a failing behavior test, make the smallest change, run `./scripts/check fast`, then `scripts/verify fast`. Report exact commands and exit codes, and anything skipped.
6. Tests use disposable git repositories built by `scripts/fixtures` or `tests/repo-sandbox.mts`, under `.local/` or `/private/tmp`. The git that tests and scripts start goes through `scripts/isolated-git.mts`, so a contributor's git config, signing key, and hooks stay out of it (unit test `isolated-git`). The app's own git calls read the person's config by design, and `personalGitOut` reads the same way where a result must agree with theirs. Each named exception is in that test. A real repository is used only read-only, through the two bar variables in `verify/features/README.md`. Never drive or stop a process you did not start.
7. Pin every dependency to an exact version. A new dependency, or a new version of one, must have been released at least 21 days before it is added. Test: `dependency-pins` checks the exact pins. The release age is checked by hand.
8. When a journey changes, update `verify/features/` and the harness in the same change.
9. Stage only named paths, never `git add .` or `-A`. Never commit secrets, private keys, or personal data.
